# 원천 변경 시나리오

`10_brokerage.sql`로 만든 테이블에 주문, 정정, 체결, 취소, 매도, 전량 체결을 한 단계씩 넣는 SQL입니다. 자동으로 실행되지 않습니다. 단계마다 Kafka 메시지 수를 먼저 예측하고 돌립니다(`docs/guide/03-flink-to-iceberg.md` 11-9).

| 파일 | 하는 일 |
|---|---|
| `01-buy-order.sql` | 매수 지정가 10주 70,000원 |
| `02-amend-price.sql` | 가격 정정 69,500원 |
| `03-partial-fill.sql` | 4주 체결, 잔고 생김 |
| `04-cancel-rest.sql` | 남은 6주 취소 |
| `05-sell-order.sql` | 매도 시장가 4주 |
| `06-sell-fill.sql` | 전량 체결, 잔고 행 삭제 |
| `07-us-past-fills.sql` | (증분 실험) 계좌 A-0002가 SPY를 지난 두 거래일에 매수 |
| `08-correct-fill-price.sql` | (증분 실험) 지난 체결의 가격 정정 |
| `09-correct-fill-date.sql` | (증분 실험) 지난 체결의 날짜 정정, 옛 거래일은 0건 |
| `check.sql` | 원천의 현재 상태 보기(읽기만) |

같은 파일을 두 번 돌리면 PK 충돌이 나거나 같은 값으로 다시 고칩니다. 처음부터 다시 하려면 세 테이블의 행을 지우고 1단계부터 돌립니다.

01 ~ 06의 시각은 psql 변수 `:now_weekday`입니다. 평일에는 `now()`와 같고, 서울 날짜로 토요일이나 일요일이면 직전 금요일 같은 시각입니다. 체결의 거래일이 주말이면 dbt 테스트 `no_weekend_trade_date`가 실패해 뒤 모델이 건너뛰어지기 때문입니다(2026-11-20 독립 검토). psql 변수라 `psql` 파일 입력(`< 파일`)이나 `-f`로 돌립니다.
