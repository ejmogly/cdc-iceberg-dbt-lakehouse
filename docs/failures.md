# 실패와 고친 것

틀렸던 것, 막혔던 것, 미리 재 보고 계획을 바꾼 것을 모읍니다. 항목마다 **무엇이 틀렸나, 어떻게 알았나, 원인, 고친 것, 다시 막는 장치** 가운데 아는 만큼 적습니다.
숫자는 그 항목이 가리키는 문서에 측정 조건과 함께 있습니다.

## F01 손익 SQL이 달러 손익의 소수를 버림

- **무엇이 틀렸나:** 손익 SQL을 처음 돌렸을 때 E01 골든 30개 가운데 6개가 어긋났습니다. 모두 미국 종목의 달러 손익 칸이었습니다.
- **어떻게 알았나:** 검증 스크립트([`eval/e01_pnl/check_sql.py`](../eval/e01_pnl/check_sql.py))가 정답과 칸마다 정확히 대조합니다.
- **원인:** 통화에 따라 소수 둘째 자리(달러)나 정수(원)로 반올림하는 CASE에서, DuckDB가 `decimal(38,2)` 갈래와 `decimal(38,0)` 갈래를 `decimal(38,0)`으로 합쳤습니다. 달러 값의 소수가 잘렸습니다.
- **고친 것:** 갈래마다 같은 자료형(`decimal(38,2)`)으로 바꾼 뒤 합칩니다. 정답과 평가 기준은 바꾸지 않았습니다.
- **다시 막는 장치:** 같은 30개로 엔진을 옮길 때마다 다시 돌립니다. 함정 목록은 [`sql/pnl/README.md`](../sql/pnl/README.md) 「엔진 함정」 1에 있습니다.

## F02 반올림 전 맞춤을 빼자 1원 어긋남

- **무엇이 틀렸나:** 마지막 반올림 전에 소수 여섯째 자리로 맞추는 안전장치를 빼고 돌려 보니, 0.5 경계에 걸린 사례(G30) 하나가 1원 어긋났습니다.
- **어떻게 알았나:** 안전장치가 진짜 문제를 가리고 있는지 보려고 일부러 뺀 시험에서 나왔습니다.
- **원인:** 나눗셈 갈래가 섞인 CASE가 매수 갈래까지 double로 바꿨고, double을 `decimal(38,18)`로 되돌릴 때 오차가 붙었습니다(700000이 700000.000000000041943040이 됨).
- **고친 것:** 나눗셈은 갈래 안에서 decimal로 바꾸고, 전량 매도는 나누지 않고 원가를 그대로 덜어 냅니다. 지금은 안전장치 없이도 30개가 맞고, 안전장치는 남겨 둡니다.
- **다시 막는 장치:** 「엔진 함정」 2에 적었습니다. 엔진을 옮기면 안전장치를 뺀 시험도 같이 돌립니다.

## F03 평가셋 점검에서 19곳이 다름

- **무엇이 틀렸나:** 평가셋이 제대로 잡혔는지 보려고 손익 화면 시안(자바스크립트)의 계산을 정답과 대조했더니 19곳이 달랐습니다.
- **원인 셋:** 연 환산 상한이 1,000%라 큰 값이 잘림(11곳). 자바스크립트 `Math.round`가 음수 0.5를 0 쪽으로 올림(7곳). 최대 낙폭의 고점을 0이 아니라 첫날 값에서 시작함(1곳).
- **고친 것:** 정답이 아니라 시안을 고쳤습니다. 규칙과 통과선은 그대로입니다.
- **배운 것:** 방식이 다른 두 계산을 대조하면 한쪽만 볼 때 못 보는 실수가 나옵니다. 다만 두 계산이 같다고 정답이 사람 눈으로 확인된 것은 아닙니다. 자세한 표는 [E01 5절](ai/experiments/E01-pnl.md)입니다.

## F04 미국 ETF 2년으로는 판정할 수 없음

- **무엇이 틀렸나:** 유사 국면 기능(E03)을 처음에는 미국 ETF 2년 시세로 판정하려 했습니다.
- **어떻게 알았나:** 실제 수익률을 보기 전에, 답을 아는 합성 세계를 만들어 판정 시험이 좋은 방법과 나쁜 방법을 가려내는지 쟀습니다. ETF 12개, 2년, 20일 범위 시험에서는 **답을 아는 방법도 6%만 통과**했습니다.
- **고친 것:** 판정 데이터를 1995년부터 있는 코스피 일별 지수(ECOS)로 바꾸고, ETF 2년은 참고로만 씁니다. 기준선을 셋으로 늘리고 셋을 모두 이겨야 값을 한다고 정했습니다.
- **배운 것:** 개발 전에 "이 데이터로 판정이 되는가"를 먼저 재면, 무엇을 만들어도 통과하거나 실패하는 시험을 피할 수 있습니다. [E03 3절](ai/experiments/E03-regime.md), [`eval/e03_regime/power_sim.py`](../eval/e03_regime/power_sim.py).

## F05 ETF를 표시한 기사가 거의 없음

- **무엇이 틀렸나:** "그때 무슨 일이" 기능(E02)은 처음에 날짜와 종목 표시로 기사를 거른 뒤 검색하려 했습니다.
- **어떻게 알았나:** 개발 전 0단계 조사에서 ETF 12개의 2년치 기사 수를 셌습니다. 하루 중앙값이 0건이었고, 크게 움직인 날 가운데 기사가 있는 날은 29.8%였습니다.
- **고친 것:** 미리 정한 규칙대로 그 형태를 버리고, 검색 대상을 날짜로 거른 검색 창마다의 전체 기사(창마다 약 400건)로 바꿨습니다. 뉴스 근거용으로 개별 기업 5개를 더했습니다. 평가 기준을 커밋하기 전에 바꿨고, 날짜와 이유를 E02 변경 기록에 남겼습니다.

## F06 삭제 이벤트의 가짜 0 값

- **무엇이 틀렸나:** 기본 `REPLICA IDENTITY`에서 삭제 이벤트의 `before`를 보면 키는 진짜인데, 키가 아닌 NOT NULL 칸은 빈 문자열과 0으로 채워져 있었습니다. 잔고 삭제를 "수량 0"으로 읽으면 틀립니다.
- **어떻게 알았나:** 2회차 실습에서 DEFAULT와 FULL을 나란히 비교했습니다.
- **고친 것:** Silver는 삭제 이벤트의 값을 믿지 않고 `op = 'd'`만 보고, 삭제된 잔고의 수량과 평균 단가는 NULL로 둡니다. 철회 때 `order_id`가 필요한 체결 테이블만 FULL로 바꿨습니다([0005](decisions/0005-replica-identity-executions-full.md)).

## F07 빈 스냅샷이 쌓임

- **무엇이 틀렸나:** 강의 공통 예제 환경에서, 데이터 변경이 없는데도 Iceberg 스냅샷이 약 100초 간격으로 계속 생겼습니다.
- **어떻게 알았나:** 1회차 실습에서 스냅샷 이력을 조회하다 발견했습니다. 3회차에도 같은 간격을 다시 봤습니다.
- **이어지는 것:** 강의 7회차의 "데이터가 없어도 커밋이 계속되어 메타데이터가 디스크를 채운 사고"와 같은 현상으로 보입니다. 원인은 7회차에 확인합니다.
- **다시 막는 장치:** 7회차에 스냅샷 만료와 파일 합치기 기준을 정하고 전후를 잽니다.

## F08 같은 값으로 다시 넣어도 이벤트가 생김 (미리 막음)

- **무엇이 문제인가:** PostgreSQL은 같은 값으로 `UPDATE`해도 새 행 판을 쓰므로 Debezium이 `u` 이벤트를 냅니다. 적재기는 늦은 정정을 잡으려고 매일 최근 며칠을 다시 받습니다.
- **고친 것:** 적재기 넷 모두 `ON CONFLICT ... DO UPDATE ... WHERE (...) IS DISTINCT FROM (...)`로 값이 바뀐 행만 고칩니다([0006](decisions/0006-batch-prices-through-cdc.md)).
- **확인:** 같은 원본을 다시 넣으면 고친 행 0, 종가 하나를 바꾸면 1행(DuckDB로 옮긴 시험, DDL 두 곳과 SQL 자리표시만 고침). PostgreSQL에서의 확인은 2026-11-12에 끝났습니다([데이터 준비](ai/data-prep.md) 「PostgreSQL 확인」, 다시 적재하면 고친 행 0, 토픽 끝 위치 그대로).

## F09 거래량 칸에 소수

- **무엇이 틀렸나:** `daily_prices.volume`은 `bigint`인데, 미국 시세 4,250행 가운데 3,094행의 거래량에 소수가 섞여 왔습니다(소수점 거래로 보임).
- **고친 것:** 지금은 정수로 반올림해 넣고 반올림한 행 수를 출력합니다. `numeric`으로 바꿀지는 정할 것입니다([`docs/ai/data-prep.md`](ai/data-prep.md) 9절).

## F10 GDELT API를 받지 못함

- **무엇이 틀렸나:** 관심도 출처 가운데 GDELT DOC API는 두 번 시험에서 모두 받지 못했습니다. 첫 호출에 429가 오고, 다시 할 때 연결이 끊겼습니다. 원인은 확인하지 못했습니다.
- **고친 것:** 적재기는 5초에 1번, 429면 기다렸다 다시 하고, 두 주제가 연달아 막히면 멈추고 기록합니다. E02 1판에서는 GDELT를 쓰지 않고, 관심도 확장에서 쓸지는 정할 것입니다.
- **대안:** 다른 환경에서 다시 시험, 15분 단위 원본 파일로 직접 세기, 공개 데이터셋 조회, 빼기.
