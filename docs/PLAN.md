## 회차별 목표

### 0주 준비

- Colima VM(CPU 6, 메모리 12GB, 디스크 60GB)과 compose 기본 profile 기동
- 끝난 모습: Kafka UI(http://localhost:18080)에서 브로커와 Connect가 보이고, Connect에 Postgres 커넥터 플러그인이 있음

1 ~ 3회차는 강의의 공통 예제(주문, 결제, 환불)로 수집과 적재를 익히고, 3회차 끝에 개인 도메인과 테이블 설계를 확정합니다. 4회차부터는 이 저장소에서 내 도메인으로 만듭니다. 11/13까지는 5 ~ 7회차를 최소 범위(Gold와 테스트, 증분 하나, 유지보수 하나)로 합니다. 공통 예제 복습은 강사 공개 저장소를 따로 받아서 하고, 그 코드는 이 저장소에 옮기지 않습니다.

### 1회차 개념과 공통 예제

- CDC를 고르는 이유와 운영 비용, 전체 복사, `updated_at` 조회, 로그 기반 CDC의 차이를 정리합니다.
- 수집 경로, 저장소, 카탈로그, 복구 상태(체크포인트)의 역할을 구분합니다.
- 같은 환불 한 건의 입력 → 금액 정정 → 삭제에서 `op`, `before`/`after`, 수집 위치(topic, partition, offset)를 먼저 예측하고 실제와 대조합니다.
- 도메인 후보를 고릅니다(확정은 3회차).
- 산출물: 공통 예제 실행 캡처, 예측 SQL, 복습 정리, 입문 가이드 학습 가이드 01

### 2회차 PostgreSQL → Debezium → Kafka 심화

- 초기 스냅샷과 이후 변경 이벤트를 구분합니다(op `r`, `c`, `u`, `d`).
- WAL, logical decoding, replication slot, publication의 역할을 확인합니다.
- 이 저장소의 기본 profile에서 `REPLICA IDENTITY` DEFAULT와 FULL의 `before` 차이를 직접 봅니다.
- 메시지 형식(JSON 또는 Avro)을 정합니다.
- Iceberg 소개 글을 읽고 무슨 일을 하는 기술인지, 궁금한 점을 메모합니다(강의 과제).
- 산출물: 공통 예제의 이벤트와 Bronze와 파일 대조 기록, `REPLICA IDENTITY` 비교 기록, Iceberg 메모

### 3회차 Flink → Iceberg Bronze 심화, 개인 설계 확정

- 체크포인트와 Iceberg 커밋, 스냅샷의 관계, 적재 지연의 시작과 끝을 구분해 잽니다.
- 도메인과 목적을 확정하고 데이터 출처와 라이선스를 `data/README.md`에 적습니다.
- 원천 테이블 2 ~ 3개마다 한 행의 의미, 컬럼과 자료형, 키와 관계, 시간과 순서 기준, 변경과 삭제 정책, 토픽과 Bronze에 남길 정보, 뒤에서 쓸 조인 키를 정합니다.
- 원천 DDL을 이 저장소 기본 profile의 PostgreSQL에 실제로 만듭니다(`infra/postgres/init/10_*.sql`).
- 수정이나 삭제가 일어나는 시나리오 1 ~ 2개와, 수집해서 확인하고 싶은 것을 적습니다.
- 원천에서 Gold까지 단계별 역할과 고민을 파이프라인 설계로 그립니다.
- Flink, Iceberg, 카탈로그, Spark, S3 호환 저장소 버전 조합을 정하고 `docs/decisions/0002`에 남깁니다.
- 산출물: `docs/design/`의 설계 초안(강의 과제 다섯 항목), 원천 DDL, 결정 기록 0002

### 4회차 Spark SQL로 Silver, 중복 제거와 재처리

- Silver 한 행과 키, 최신을 고르는 기준(원천 LSN), 삭제 표시 방법을 Silver 설계서로 정리합니다(강의 과제).
- 내 도메인의 커넥터, lake와 flink profile, Bronze 적재를 이 저장소에 올립니다.
- 같은 키의 여러 이벤트에서 최신 상태를 고릅니다.
- `MERGE`와 삭제 표시로 Silver를 갱신하고, 삭제 뒤에 옛 값이 되살아나지 않게 적용 순서를 점검합니다.
- 같은 이벤트 재전달, Flink 작업 중단과 체크포인트 복구 뒤 누락, 중복을 검증합니다.
- 산출물: Silver 설계서, Bronze 적재 작업, Silver SQL, 생성과 수정과 삭제 검증 기록, 장애와 복구 기록

### 5회차 dbt로 Silver core와 Gold 지표, 데이터 테스트

- 여러 마트가 함께 쓰는 Silver core(fact, dim)를 만들고, 그 위에 Gold 지표를 정의합니다.
- 지표 2 ~ 3개의 정의, 집계 단위, 갱신 주기, 수정과 삭제 때 기대 결과를 지표 정의서로 씁니다.
- `source`, `ref`로 의존성과 실행 순서를 만듭니다.
- 조인 때문에 집계 값이 부풀어 오르는 경우를 확인합니다.
- `not_null`, `unique`, `relationships` 같은 테스트와 지표 계산 기준 문서를 씁니다.
- 산출물: 지표 정의서, `dbt/` 프로젝트, Gold 모델, 테스트와 문서

### 6회차 증분 처리, 지연, 정정, 삭제

- 강의 공지(11/11 받음): dbt 모델 계약과 OpenMetadata 컬럼 리니지, Iceberg changelog view, 영향 키 전파와 옛 날짜 다시 묶기, plan과 progress 저장 순서, 재시도 멱등성, Airflow 30분 주기.
- 전체 재계산과 증분 처리를 비교합니다.
- 변경의 영향을 받는 키와 기간을 찾고, 원천 삭제를 마트에 반영하는 정책을 구현합니다.
- 특정 기간을 다시 처리하는 백필과 반복 실행을 검증합니다.
- 산출물: 증분 모델, 백필 절차, 전체 재계산과 증분 결과 비교

### 7회차 작은 파일, 파티션, 쿼리 튜닝

- 강의 공지(11/11 받음): 메타데이터가 디스크를 채운 사고, 유지보수 도구 네 가지(`rewrite_data_files`, `expire_snapshots`, `remove_orphan_files`, `rewrite_manifests`), 작은 커밋 120번 실험, progress 스냅샷을 지우는 함정, 리뷰 질문지로 프로젝트 점검.
- Iceberg 파일 수, 크기와 Spark 실행 계획을 확인합니다.
- 체크포인트 주기를 바꾸며 커밋 간격, 파일 수, 반영 지연을 비교합니다.
- Kafka lag, Flink backpressure, 체크포인트 소요 시간으로 지연 구간을 봅니다.
- 파일 합치기와 파티션 설계를 비교하고, 스냅샷 보존 기간을 정합니다.
- 산출물: 개선 가설, 측정 조건, 성능 비교 보고서와 보존 정책

### 8회차 전체 운영 점검

- 구간별 지연, 중단, 재시작 뒤 누락, 중복과 집계 결과를 점검합니다.
- 산출물: `airflow/dags/`, 전체 흐름 검증 결과, 운영 체크리스트, 보완 목록

### 확장: 무엇이 관심을 끄나 (8회차 뒤 또는 마무리 주, 선택)

- 공식 무료 출처(GDELT 기사 수와 어조, 위키백과 조회수, 종목 뉴스 감성, 네이버 검색어 트렌드)에서 정해 둔 주제의 관심도를 날짜별로 모아 `source.attention_daily`에 넣고, 시세와 같은 길로 CDC합니다.

- 산출물: 수집기, 주제 목록(`topics.csv`), 관심도 Gold 모델과 테스트, 상관과 인과 점검 기록

### AI 트랙: 포트폴리오 타임머신 (11/13 최소 범위, 12/4까지 화면과 E02)
