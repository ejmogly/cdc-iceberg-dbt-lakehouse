## 회차별 목표

### 0주 준비

- Colima VM(CPU 6, 메모리 12GB, 디스크 60GB)과 compose 기본 profile 기동
- 끝난 모습: Kafka UI(http://localhost:18080)에서 브로커와 Connect가 보이고, Connect에 Postgres 커넥터 플러그인이 있음

### 1회차 설계

- 누가 어떤 결정을 내릴 때 쓰는 데이터인지부터 정합니다.
- 도메인과 데이터셋을 고르고 출처와 라이선스를 `data/README.md`에 적습니다.
- 원천 테이블 2~4개의 키와 관계, 지표 2~3개의 집계 단위와 갱신 주기를 정합니다.
- 데이터가 수정·삭제될 때 지표가 어떻게 달라져야 하는지 적습니다.
- 전체·증분 배치 대신 CDC를 고르는 이유를 정리합니다.
- 산출물: `docs/design/`의 제안서, ERD, 지표 정의서, 아키텍처 초안

### 2회차 PostgreSQL → Debezium → Kafka

- 초기 스냅샷과 이후 변경 이벤트를 구분합니다(op `r`, `c`, `u`, `d`).
- WAL, logical decoding, replication slot, publication의 역할을 확인합니다.
- `REPLICA IDENTITY` 설정에 따라 `before` 값이 어떻게 달라지는지 봅니다.
- 원천에서 INSERT·UPDATE·DELETE를 하고 Kafka 이벤트와 대조합니다.
- 산출물: `infra/postgres/init/10_*.sql`(원천 DDL), `infra/connect/source-postgres.json`, 변경 시나리오와 이벤트 확인 기록

### 3회차 Flink → Iceberg Bronze

- Flink·Iceberg·카탈로그 버전 조합을 정하고 `docs/decisions/0002`에 남깁니다.
- Kafka source와 Iceberg sink를 연결해 변경 이력을 그대로 적재합니다.
- 체크포인트와 Iceberg 커밋·스냅샷의 관계를 관찰합니다.
- 원천 변경 시각부터 Iceberg에서 조회 가능한 시각까지 지연을 잽니다.
- 산출물: Flink 적재 작업, Bronze 테이블, 이벤트 검증과 적재 지연 기록

### 4회차 Spark SQL로 Silver, 중복 제거와 재처리

- 같은 키의 여러 이벤트에서 최신 상태를 고릅니다.
- `MERGE`와 삭제 표시로 Silver를 갱신하고, 삭제 뒤에 옛 값이 되살아나지 않게 적용 순서를 점검합니다.
- 같은 이벤트 재전달, Flink 작업 중단과 체크포인트 복구 뒤 누락·중복을 검증합니다.
- 산출물: Silver SQL, 생성·수정·삭제 검증, 장애·복구 기록

### 5회차 dbt 모델링과 데이터 품질

- `source`·`ref`로 의존성과 실행 순서를 만들고, staging → intermediate → mart로 나눕니다.
- 조인 때문에 집계 값이 부풀어 오르는 경우를 확인합니다.
- `not_null`, `unique`, `relationships` 같은 테스트와 지표 계산 기준 문서를 씁니다.
- 산출물: `dbt/` 프로젝트, 분석 마트, 테스트와 문서

### 6회차 증분 처리, 지연·정정·삭제

- 전체 재계산과 증분 처리를 비교합니다.
- 변경의 영향을 받는 키와 기간을 찾고, 원천 삭제를 마트에 반영하는 정책을 구현합니다.
- 특정 기간을 다시 처리하는 백필과 반복 실행을 검증합니다.
- 산출물: 증분 모델, 백필 절차, 전체·증분 결과 비교

### 7회차 작은 파일, 파티션, 쿼리 튜닝

- Iceberg 파일 수·크기와 Spark 실행 계획을 확인합니다.
- 체크포인트 주기를 바꾸며 커밋 간격, 파일 수, 반영 지연을 비교합니다.
- Kafka lag, Flink backpressure, 체크포인트 소요 시간으로 지연 구간을 봅니다.
- 파일 합치기와 파티션 설계를 비교하고, 스냅샷 보존 기간을 정합니다.
- 산출물: 개선 가설, 측정 조건, 성능 비교 보고서와 보존 정책

### 8회차 전체 운영 점검

- PostgreSQL 변경부터 마트까지 전체 흐름을 검증합니다.
- Airflow로 변환·테스트 작업의 순서와 재시도를 구성합니다.
- 구간별 지연, 중단·재시작 뒤 누락·중복과 집계 결과를 점검합니다.
- 산출물: `airflow/dags/`, 전체 흐름 검증 결과, 운영 체크리스트, 보완 목록

### 마무리

- README에 아키텍처, 실행 방법, 결과와 측정 조건을 정리합니다.
- 발표 자료를 만듭니다.
- 공개 방법(이 저장소를 그대로 올릴지, 다른 기기에서 다시 만들지)과 시점을 정합니다.
