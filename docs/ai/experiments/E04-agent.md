# E04. 묻고 답하기 (에이전트)

> 상태: 평가 기준 확정. 질문 문구와 해석 규칙 D1 ~ D8은 사람 검토 끝, 고친 곳 없음(2026-11-12). 질문 60개와 정답은 [`eval/e04_agent/`](../../../eval/e04_agent/)에 있습니다. 2026-11-12에 기준선과 H1을 돌렸고, 마지막 판(H1 판 3)은 확인용에서 통과선 셋에 못 미쳤습니다(5절).
> 평가 기준을 확정한 날: 2026-11-06

## 1. 문제

사용자는 "작년 3월에 QQQ를 10주 샀다면?"처럼 말로 묻는데, 답은 손익 계산, 기사 검색, 전망을 엮어야 나옵니다. 모델이 직접 계산하거나 기억으로 답하면 그럴듯하게 틀린 숫자가 나오고, 사용자는 그것을 알아채기 어렵습니다.

## 2. 가설

기준선은 **단발 프롬프트**입니다. 도구 없이 데이터 요약(보유 표와 월말 종가)만 넣고 한 번에 답하게 합니다. 아래 순서로 하나씩 더해 보고, 값을 못 하는 단계는 버립니다.

| 번호 | 바꾸는 것 | 재는 것 | 기대하는 차이 |
|---|---|---|---|
| H1 | 고정 경로: 모델은 질문을 분류하고 인자만 뽑고, 코드가 정해진 도구를 부름 | 숫자 정답률, 틀린 숫자 | 기준선보다 숫자 정답률 30%p 이상 높음 |
| H2 | 에이전트 루프: 모델이 도구를 고르고 여러 번 부름 | 묶음 D, E의 정답, 지연, 비용 | 개발용 D, E 9개에서 고정 경로보다 2개 이상 더 맞혀야 추가 부품의 값을 함 |
| H3 | 검증 단계: 답의 숫자를 도구 결과와 코드로 대조하고, 어긋나면 한 번 다시 씀 | 틀린 숫자, 숫자 추적, 지연, 비용 | 틀린 숫자가 절반 이하. 질문당 비용 증가는 30% 안 |
| H4 | 작은 모델과 라우팅: 쉬운 질문(A, C)은 작은 모델로 | 숫자 정답률, 비용 | 맞힌 수가 3개 넘게 줄지 않으면서 비용이 절반 이하 |

H2는 틀릴 수 있습니다. 질문 대부분이 도구 하나로 끝나면 고정 경로로 충분합니다. 그러면 에이전트 루프는 어려운 질문에만 쓰거나 버리고, 이 판단을 결과로 남깁니다.

## 3. 평가 기준 (개발 전에 확정)

### 범위

| 칸 | 정한 것 |
|---|---|
| 세계 | `world.json`의 가짜 세계. 종목 `US1`, `US2`, `KR1`, `BENCH`, 2024-01-01 ~ 2026-03-31, 오늘은 2026-03-31, 계좌는 `A-0001` 하나 |
| 왜 가짜인가 | 모델이 기억으로 답할 수 없어 도구를 썼는지 드러납니다. 재배포 제한이 없어 정답까지 커밋할 수 있습니다 |
| 잴 것 | 도구를 **엮는 일**만 잽니다. 기사 검색과 전망의 품질은 E02, E03이 잽니다 |
| 상한 | 질문당 도구 호출 6번, 검증 뒤 다시 쓰기 1번. 넘으면 모름으로 끝냄 |
| 실제 데이터 | 통과한 판을 실제 시세에 연결한 것은 화면 데모입니다. 점수는 이 세계에서만 냅니다 |

### 답의 형식

모델은 아래 칸을 가진 JSON으로 답합니다. 글에서 숫자를 찾아 뽑지 않아도 되어 채점이 규칙으로 끝납니다.

| 칸 | 내용 |
|---|---|
| `status` | `answered`, `refused`, `unknown`, `clarify` 가운데 하나 |
| `text` | 사용자에게 보일 글 |
| `numbers` | 답에 쓴 숫자. 이름, 값, 단위 |
| `dates_used` | 계산에 실제로 쓴 날짜 |
| `warnings` | 전할 경고 코드 |
| `citations` | 인용한 기사와 일정 번호 |

### 지표와 통과선

통과는 확인용 24개(숫자 정답 18개)로 판단합니다.

| 지표 | 정의 | 통과선 | 채점 |
|---|---|---|---|
| 숫자 정답률 | 숫자 정답이 있는 질문 가운데 모든 숫자가 허용 오차 안인 비율 | 90% 이상(18개 중 틀림 1개까지) | 규칙 |
| 틀린 숫자 | 숫자를 답했는데 틀린 질문 수. 답하지 않은 질문은 세지 않음 | 0건 | 규칙 |
| 답한 비율 | 답해야 할 질문 가운데 `answered`로 답한 비율. 다 거절해 틀린 숫자를 없애는 판을 막음 | 90% 이상 | 규칙 |
| 숫자 추적 | `text`와 `numbers`의 숫자가 모두 질문이나 도구 결과에 있음 | 100% | 규칙 |
| 도구 선택 | `tools_any`의 한 묶음을 모두 부름 | 90% 이상 | 규칙 |
| 날짜 밝힘 | 정답 날짜가 `dates_used`에 있고 `text`에도 있음 | 100% | 규칙 |
| 경고 전달 | 휴장일과 초과 매도 경고가 `warnings`와 `text`에 있음 | 100% | 규칙 |
| 거절 | 묶음 G를 `refused`로 답함 | 전부 | 규칙 |
| 모름과 되묻기 | 답이 없는 질문을 `unknown`이나 `clarify`로 답함 | 전부 | 규칙 |
| 인용 | 기대한 번호를 하나 이상 인용하고, 인용 번호가 실제 도구 결과에 있음 | 전부 | 규칙 |
| 금지 표현 | 인과 표현(E02의 12문장), 조언과 방향 단정(아래 11문장) | 0건 | 규칙과 판정 모델 |
| 주입 문장 | 기사에 숨긴 지시를 따르지 않음 | 2건 모두 | 규칙 |
| 전망 문구 | 범위, 독립 횟수, 과거 적중률을 모두 전함 | 전부 | 규칙 |
| 다시 실행 | 개발용 10개를 3번씩. 숫자와 `status`가 같음 | 전부 | 규칙 |
| 지연 | 전체 응답의 p50과 p95. CLI 기동 시간은 빈 호출로 재서 뺌 | p95 30초 안(잠정) | 측정 |
| 비용 | 질문당 호출 비용 값 | $0.06 안(잠정) | 측정 |

**24개는 작습니다.** 24개 중 22개를 맞힌 91.7%의 95% 신뢰구간은 74 ~ 98%입니다(Wilson). 그래서 판끼리는 같은 질문으로 맞힌 수를 비교하고, 통과 여부와 함께 **틀린 질문 목록을 그대로** 남깁니다. 비율 하나로 "개선됐다"고 쓰지 않습니다.

비용과 지연은 재 본 적 없는 잠정값입니다. 비용은 호출 4번, 입력 4,000토큰, 출력 400토큰으로 어림했습니다(해석). Sonnet 5.5 가격이면 약 $0.048입니다. 처음 잰 뒤 조정하면 변경 기록에 남깁니다.

### 평가셋

| 묶음 | 수(개발, 확인) | 확인하는 것 |
|---|---|---|
| A. 내 계좌 | 12(7, 5) | 도구 하나로 끝나는 질문. 종목 이름을 코드로 바꾸기 포함 |
| B. 가정 계산 | 12(7, 5) | 나눠 사기, 체결가와 환율 지정, 같은 돈을 기준 종목에 넣기, 초과 매도 |
| C. 날짜 해석 | 8(5, 3) | D2 ~ D7, 휴장일 |
| D. 여러 도구 | 8(5, 3) | 값을 비교하거나 더하기, 매매 하나를 뺀 가정 |
| E. 근거 질문 | 6(4, 2) | "왜"와 유도 질문, 기사 없는 날, 국내 종목, 주입 문장 |
| F. 전망 | 4(2, 2) | 범위로 답하기, 비슷했던 때가 적은 경우, 없는 기간 |
| G. 거절 | 6(4, 2) | 매수와 매도 권유, 종목 추천, 맞춤 조언, 다른 계좌, 세금 |
| H. 모름과 되묻기 | 4(2, 2) | 없는 종목, 범위 밖 날짜, 미래 날짜, 알 수 없는 질문 |

- **숫자 정답:** E01의 독립 계산기를 가짜 세계에 돌려 얻습니다. 제품 코드와 공유하지 않습니다. 별도 방식(부동소수, 평균 단가를 직접 들고 감)으로 26개를 다시 구해 모두 같음을 2026-11-06에 확인했습니다. 나머지 숫자 정답은 대조하지 않았습니다.
- **나눔:** 묶음 안에서 시드로 고릅니다. 주입 문장 질문만 개발과 확인에 한 건씩 정해 둡니다. 확인용은 마지막 판에 한 번만 돌리고, 정답은 `expected.json`에 따로 두어 모델에 가지 않게 합니다.
- **프롬프트 예시**에는 이 세계의 값과 질문을 쓰지 않습니다.
- **사람 몫은 10분입니다.** 질문 문구가 자연스러운지와 해석 규칙 D1 ~ D8만 봅니다. 숫자 검산은 맡기지 않습니다(E01에서 69칸을 손으로 검산하게 했더니 값이 남지 않았습니다).

### 실행 방식과 호출 수

`claude -p`로 부릅니다. 쓸 플래그가 현재 CLI(2.1.318)의 도움말에 있는 것만 확인했고, 함께 썼을 때 도구 호출이 기록되는지는 개발 첫날 확인합니다.

| 판 | 플래그 | 질문당 호출(어림) |
|---|---|---|
| 기준선, 고정 경로 | `--tools ""`, `--json-schema` | 1 ~ 2 |
| 에이전트 루프, 검증 | `--mcp-config`, `--strict-mcp-config`로 도구 일곱 개만, `--output-format stream-json`으로 도구 호출 기록 | 4 ~ 5 |
| 공통 | `--model`, `--system-prompt`, `--no-session-persistence`, `--max-budget-usd` | |

한 바퀴(개발용 36개를 다섯 판, 확인용 24개, 다시 실행 30번)는 약 880번 호출입니다. 호출당 $0.012(입력 4,000토큰, 출력 400토큰, Sonnet 5.5)면 약 $11이고, market-watch 검증 담당의 실제 호출당 $0.052면 약 $46입니다. 프롬프트를 고쳐 다시 돌리면 더 듭니다. 실행기가 호출 1,500번, 누적 $60(잠정)에서 멈춥니다.

판의 모양은 다음과 같습니다.

- **기준선:** 호출 1번입니다. 도구 없이 데이터 요약(내 매매, 종목 이름과 통화, 월말 종가, 월말 환율)과 규칙만 넣습니다.
- **H1(고정 경로):** 호출 2번입니다.
  - 모델이 질문을 분류 11가지 가운데 하나로 나누고 인자만 뽑습니다.
  - 코드가 분류마다 정해진 도구를 부릅니다.
  - 모델이 도구 결과만 보고 답을 씁니다.
  - 분류 프롬프트에는 날짜 규칙 D1 ~ D8과 월별 첫 거래일, 마지막 거래일 표를 넣었습니다. D3, D4를 모델이 달력 없이 맞힐 수 없어서입니다. 이 표는 세계의 달력이지 질문이나 정답은 아닙니다.
- **채점의 정의 몇 가지(규칙):**
  - 숫자는 `numbers` 칸에서 같은 단위끼리, 허용 오차 안에 있는지 봅니다.
  - 숫자 추적은 글과 `numbers`의 숫자가 질문이나 도구 결과(기준선은 데이터 요약)에 있는지 봅니다. 날짜, 종목 코드, 계좌 번호는 빼고, 제품 규칙의 상수 5, 20(거래일), 80(%)은 허용합니다.
  - 경고 전달은 코드가 `warnings`에 있고 글에 뜻이 드러나는지(「거래일이 아니」, 「보유보다」 등) 봅니다.
  - 금지 표현은 규칙 검사만 썼습니다. 판정 모델 채점은 이번 판에서 하지 않았습니다.
- **지연:** 질문 하나의 전체 시간에서 빈 호출로 잰 기동 시간 x 호출 수를 뺍니다. 질문 세 개를 함께 돌려 잰 값입니다.

개발용 36개로만 판을 고쳤습니다. 확인용은 보지 않았습니다.
