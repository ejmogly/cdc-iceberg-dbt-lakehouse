# 0014 전체 탭은 종목마다 같은 계산을 더하고, Gold에는 계좌별 손익 마트를 둔다

- 날짜: 2026-11-19
- 상태: 결정(담당자 「권장안대로」), 확인함

## 맥락

화면은 한 종목씩만 보였습니다. 담당자가 「전체 투자를 보는 곳이 있으면 좋겠다」고 했습니다(11/19 중간 판). 저장 파일에는 종목마다 매매가 있고, 레이크의 Gold 손익 마트(`pnl_position`)는 이미 계좌 x 종목 단위입니다([0013](0013-screen-accounts-and-transfer-in.md)).

## 결정

1. **화면**: 새 탭 「전체」. 저장한 모든 종목(지금 고치는 종목 포함)을 지금 기준일로 다시 세어 더합니다(`POST /api/portfolio`). 종목마다 손익 API와 같은 계산(`ai/holdings.run`, 증권사별과 지금 잔고 포함)을 부르고, 원화 손익, 실현, 평가, 넣은 원화는 그 값을 그대로 더합니다.
2. **평가액**: 남은 수량 x 기준일(이전 마지막 거래일) 종가 x 그날 매매기준율(국내 1)을 계좌, 종목마다 원 단위로 반올림해 더합니다. 비중은 평가액으로 셉니다.
3. **더하지 않는 것**: SPY 비교와 연 환산 수익률은 돈이 들어간 때가 종목마다 달라 더하지 않고 종목 요약에서 봅니다. 틀린 줄이 있는 종목은 전체를 실패시키지 않고 빼고 까닭을 적습니다.
4. **Gold**: `lake.gold.mart_account_pnl`(계좌별 실현, 평가, 합계, 넣은 원화, 평가액, 종목 수)을 `pnl_position`에서 만듭니다. 평가액 규칙은 화면과 같습니다. `loaders/screen_trades.py --verify`가 화면 전체 탭의 증권사별 줄(Gold 기준일로 다시 셈)과 계좌마다 견줍니다.

## 영향

- 손익 SQL과 E01 골든은 그대로입니다. 전체 탭은 종목 계산을 더하기만 합니다.
- 여러 증권사 종목의 넣은 원화를 계좌 합으로 바꿨습니다. 계좌마다 원 단위로 반올림한 합이 합친 계산과 1원 달라 전체와 증권사별 합이 어긋났기 때문입니다. 단순 수익률도 그 합으로 다시 셉니다.
- 화면 머리(종목 이름)는 전체 탭에서도 그대로 보입니다. 전체 탭의 글이 「저장한 모든 종목」임을 밝힙니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
|---|---|
| 전체 손익을 한 번의 계산으로(모든 종목을 한 장부에) | 손익 SQL의 계산 단위가 종목이라 바꿔야 하고, 종목 화면의 숫자와 따로 놀 수 있음 |
| 전체에도 SPY 비교와 연 환산 | 종목마다 돈이 들어간 때가 달라 더한 값의 뜻이 흐림. 합친 현금 흐름으로 따로 세는 것은 다음 판 |
| 레이크 없이 화면만 | 부트캠프 내용(dbt 마트, 대조)을 디벨롭하는 목적에 맞지 않음 |
