# 0003 합성 거래 데이터와 공공 시세

- 날짜: 2026-11-06
- 상태: 결정

## 맥락

이 프로젝트의 질문은 "주문이 정정되거나 취소되고 체결이나 종가가 정정돼도, 지표가 원천과 맞는가"입니다.
그러려면 정정과 삭제가 자주 일어나는 데이터가 필요합니다.

- 실제 고객의 주문, 체결, 잔고는 공개된 곳이 없습니다.
- 저장소를 공개할 예정이라, 데이터마다 약관이 분명해야 합니다.
- 숫자가 모두 가짜면 "제공처가 지난 값을 고친다" 같은 실제 데이터의 변화를 볼 수 없습니다.

## 결정

1. 도메인은 **가상의 모바일 증권 앱**입니다. 실제 증권사 이름은 쓰지 않습니다.
2. 주문(`orders`), 체결(`executions`), 잔고(`holdings`)는 **합성 데이터**입니다. 저장소에는 시나리오 SQL과 생성기 코드만 둡니다.
3. 일별 시세(`daily_prices`)만 **실제 공공 데이터**입니다.
   - 국내 2종목: 공공데이터포털 금융위원회_주식시세정보
   - 미국 17종목(ETF 12개, 개별 기업 5개): Massive 무료 요금제 일별 집계
4. 받은 원본은 `data/raw/`(git 제외)에만 둡니다. 저장소에는 받는 코드와 집계 숫자만 남깁니다. 뉴스는 제목과 요약만 받고 본문은 받지 않습니다.
5. 종목 기준 정보(이름, 시장, 통화, 자산군)는 원천 테이블로 두지 않고 `loaders/instruments.csv` 하나로 둡니다. 5회차에 dbt seed로 씁니다. 계좌 테이블도 두지 않고 `account_id` 값만 씁니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
|---|---|
| 시세까지 모두 합성 | 제공처의 값 정정, 휴장일 차이, 수정주가 변화처럼 실제 데이터에서 생기는 일을 볼 수 없음 |
| 공개된 거래 데이터셋 | 정정과 삭제 이력이 없고, 데이터셋마다 약관이 달라 공개 저장소에 다시 싣기 어려움 |
| 비공식 시세 경로 | 약관이 분명하지 않아 공개 저장소에 맞지 않음 |
| 종목, 계좌를 원천 테이블로 | 거의 바뀌지 않아 CDC로 보여 줄 것이 없고 테이블만 늘어남 |

## 결과

- 시세는 재배포할 수 없으므로, 저장소를 받은 사람은 각자 키를 받아야 실제 시세를 볼 수 있습니다. 그래서 키 없이 도는 확인(가짜 시세로 만든 E01 사례)을 따로 둡니다(`make check`).
- Massive 일별 집계의 수정 옵션은 분배금을 반영하지 않으므로, 이 프로젝트의 수익률은 모두 가격 수익률입니다.
- 출처와 약관은 [`data/README.md`](../../data/README.md)에 있습니다.
