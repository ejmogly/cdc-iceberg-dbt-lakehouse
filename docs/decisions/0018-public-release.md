# 0018 공개는 git 기록을 고쳐 옮기고, 학습 가이드는 빼고, 준비되는 대로 한다

- 날짜: 2026-11-24
- 상태: 결정(담당자), 실행 전

## 맥락

공개 전 검토(2026-11-20 독립 검토, 11/24 마지막 검토)에서 지금 파일은 공개 검사를 통과했지만, git 기록에는 공개에 맞지 않는 것이 남아 있습니다. 개인 표기 1곳, 실제 매매처럼 보이는 시험 값 1벌, 공개에 맞지 않는 표현 몇 곳(첫 커밋부터)입니다. 학습 가이드(`docs/guide/` 00 ~ 08)는 강의를 듣고 다시 쓴 글이라 강의 쪽 2차 저작으로 읽힐 수 있습니다. 한편 [0009](0009-commit-evaluation-before-development.md)는 git 기록의 날짜와 순서를 「평가 기준을 개발 전에 커밋」한 증거로 씁니다.

## 결정

1. **기록은 고쳐서 옮깁니다.** 원래 저장소의 사본에서 `git filter-repo`로 공개에 맞지 않는 글자만 바꿉니다. 커밋 날짜, 순서, 메시지는 그대로 두어 0009의 증거를 지킵니다. 바꿀 낱말 목록은 저장소 밖의 규칙 파일에만 둡니다.
2. **해시는 모두 바뀝니다.** 공개본의 마지막 커밋에서 문서 속 옛 해시를 새 해시로 바꾸고, 옛 해시와 새 해시의 대응표(`docs/commit-map.md`)를 남깁니다.
3. **학습 가이드는 공개본과 그 기록에서 뺍니다.** 강의 쪽 허락을 받으면 더합니다. 가이드는 git 밖 폴더로 옮겨 계속 씁니다.
4. **라이선스는 붙이지 않습니다.** 코드를 볼 수는 있지만 가져다 쓸 권리는 주지 않습니다. 시세와 기사 데이터는 저장소에 없고 제공처 약관을 따릅니다([`data/README.md`](../../data/README.md)).
5. **공개는 준비되는 대로 합니다.** 공개본 검사(기록 전체의 공개 검사 0건, 새로 받아 `make check`)가 끝나면 담당자가 개인 계정에 저장소를 비공개로 만들고 push한 뒤, 확인하고 공개로 바꿉니다.
6. **소개 페이지는 비공개로 둡니다.** 실제 시세가 보이는 캡처라 재배포 금지에 걸립니다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
|---|---|
| 기록 없이 한 커밋으로 새로 시작 | 가장 단순하지만 순서의 증거가 sha256 잠금 기록만 남고, README와 0009의 「git 날짜가 증거」를 고쳐야 함 |
| 기록 그대로 공개 | 개인 표기와 공개에 맞지 않는 표현이 기록에 남음 |
| 가이드를 함께 공개 | 강의 쪽 허락 전에는 2차 저작 문제가 생길 수 있음 |
| MIT 라이선스 | 담당자가 고르지 않음 |

## 영향

- 공개본의 커밋 날짜와 순서는 원래 저장소와 같고, 내용만 규칙 파일대로 바뀝니다. 학습 가이드만 바꾼 커밋 2개(11/13, 11/16)는 바뀐 것이 없어져 공개본 기록에 없고, 대응표에 그렇게 적습니다.
- 문서의 학습 가이드 링크는 「강의 쪽 허락 뒤 공개」로 바꿉니다.
- 공개 뒤 작업 폴더를 공개본으로 바꿀지(원래 저장소는 백업으로)는 공개를 마친 뒤 정합니다.
